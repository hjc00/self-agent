## Context

当前悬浮球外观全部硬编码在 `src/ball.html`：紫色渐变背景 (`#667eea → #764ba2`)、地球 SVG 前景图标、64×64 固定尺寸、圆形 (`border-radius: 50%`)。系统托盘图标在 main.js 中以 16×16 RGBA buffer 程序化生成（硬编码紫色 `rgb(102,126,234)`）。

该功能需要在设置窗口中提供外观配置界面，保存到 config.json，并通过 IPC 将变更实时推送到悬浮球窗口和托盘图标。

### 约束

- `contextIsolation: true`，渲染进程不能直接读取本地文件
- 托盘图标必须通过 `nativeImage` 程序化生成
- 悬浮球窗口为 frameless + transparent

## Goals / Non-Goals

**Goals:**
- 用户可通过设置窗口配置前景图标、背景渐变（双色）、大小（48–128 px）、形状（圆形/圆角方形/正方形）
- 前景图标支持 PNG / JPG / SVG，通过系统文件对话框选择
- 保存后立刻生效，不需要重启
- 托盘图标跟随背景色和前景图标联动更新
- 图标文件无效/缺失时回退默认并警告用户

**Non-Goals:**
- 不支持图标拖拽到球上
- 不支持每个项目独立外观（全局外观）
- 不改变 DEPLOY.md（那是另一个变更的事）

## Decisions

### 1. 图标存储：data URI 而非文件路径

**选型**：用户选择图标后，主进程用 `nativeImage` 读取并缩放到 256×256 上限，转为 PNG 的 base64 data URI 存入 config.json 的 `icon_data` 字段。

**理由**：
- 渲染进程有 `contextIsolation`，不能直接读文件，data URI 可以直接写入 CSS `background-image`
- 避免用户移动/删除图标文件导致图标丢失
- 配置文件自包含，便于备份迁移

**替代方案**：存文件路径 + 主进程每次读取转 data URI 返回。更省存储空间，但文件被移动后会静默失效。未采纳。

### 2. 配置结构调整：`appearance` 子对象

```json
{
  "ball_x": 100,
  "ball_y": 100,
  "auto_start": false,
  "appearance": {
    "icon_data": "",
    "color1": "#667eea",
    "color2": "#764ba2",
    "size": 64,
    "shape": "circle"
  }
}
```

`icon_data` 为空字符串表示使用默认地球 SVG。`color1`/`color2` 相同时即为单色。

### 3. 托盘图标生成策略

托盘为 16×16 像素。生成逻辑：
1. 创建 16×16 RGBA buffer
2. 用 `color1`/`color2` 填充圆形区域（渐变采样）
3. 如果 `icon_data` 非空，将缩小的图标叠加在中心 10×10 区域
4. 如果 `icon_data` 为空，不叠加（保持纯色圆形）

**理由**：16×16 下任何图像都高度模糊，纯色圆点 + 主色调最具辨识度。

### 4. IPC 设计：拉取 + 推送模式

- 设置窗口打开时**拉取**当前外观配置（`get-appearance`）
- 用户保存时**推送**到主进程（`save-appearance`）
- 主进程保存后**广播** `appearance-changed` 到悬浮球窗口（`webContents.send`）

**理由**：单向数据流。设置窗口是唯一写入方，主进程是协调者，悬浮球是消费者。

### 5. 设置窗口 UI 布局

```
┌─────────────────────────────────────────┐
│  外观设置                                │
│                                          │
│  前景图标   [选择文件...]    [预览 48×48]  │
│                                          │
│  渐变色 1   [████████]  #667eea          │
│  渐变色 2   [████████]  #764ba2          │
│                                          │
│  大小       [━━━●━━━━━]  64 px           │
│                                          │
│  形状       ○ 圆形  ◉ 圆角方形  □ 正方形  │
│                                          │
│  ──────────────────────────              │
│  ☐ 开机自启                              │
└─────────────────────────────────────────┘
```

颜色输入使用 `<input type="color">`，大小使用 `<input type="range">`，形状使用三个 radio button。
设置窗口尺寸从 400×200 扩展为 400×380。

## Risks / Trade-offs

- **config.json 体积增大**：base64 图标字符串 ~50KB（256×256 PNG），但配置文件不频繁读写，可接受
  - 缓解：主进程 resize 图标到 256×256 上限防止超大文件
- **托盘图标可辨识度低**：用户选择复杂图片缩到 16×16 可能看不清
  - 缓解：托盘只跟背景色走，不强行叠加图标；用户预览区域展示实际托盘效果
- **SVG 文件转 raster**：`nativeImage` 对 SVG 的支持有限
  - 缓解：主进程在 `pick-icon` handler 中做格式检测；SVG 尝试通过 `nativeImage.createFromDataURL` 渲染，失败则返回错误告知用户
- **窗口 resize 动画**：改变 size 配置时窗口瞬间变化
  - 接受，不做动画
